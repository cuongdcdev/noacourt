## Deviations and issues
1. **Coordinator change not applied.** A mid-run message asked for a 15 minute market. It arrived after `market_create_link` had been called and after both transactions had already been signed and confirmed, so there was nothing unsigned to discard. Market 26 kept the 19:28Z observation. No second market was created because that would have needed another 100 NPOINT stake beyond the authorized amount.
2. MCP `market_status`, `verdict_get` failed from about 19:04 to 19:13 with "NEAR RPC query failed across 3 endpoint(s)" (server-side). My own view calls to the Court contract worked, and the keeper was healthy. Report to the MCP owner.
3. Noa market page showed no description/rules for the first minutes after publishing (see above).
4. `wallet.ts` change: it was testnet-only. It now reads `NETWORK=mainnet` (default stays testnet) and switches RPC list (fastnear mainnet, then near.org), Noa contract (`v3.noamarket.near`), token (`npoint.noamarket.near`), credentials directory (`~/.near-credentials/mainnet`), and default sign base (`https://court.noamarket.xyz`). One regex for the broadcast-error check was loosened to `failed across \w+ RPC endpoints`. Typecheck (`tsc --noEmit` in e2e) showed no errors. No other file under `e2e/` and nothing under `apps/mcp/src` was edited.
5. Creator 100 NPOINT stake came back to the creator's Noa internal balance with the finalize (net +14.2445 vs before). I did not analyze the split (stake, creator fee share 0.8+ NPOINT, residual); not independently verified.
