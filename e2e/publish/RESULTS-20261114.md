## Bugs / findings
1. `e2e/publish/run.ts:38` `const accountId = parsed.account_id ?? view.creator;` Standard near-cli key files (user2/user3 here) have no `account_id` field, so the check at line 39 `accountId !== view.creator` is vacuous. A wrong account's key file is silently accepted (`keySigner(creator, otherKey)`). When the market is already published the read-back short-circuits and prints `published`, exit 0. For an unpublished market it would fail at Noa login (`login_failed`). Observed: `run.ts` with user3's key on user2's market 87 printed `result: published` with no error.
2. Sharing the live DB with the public server is unsafe: `apps/mcp/dist/sign/store.js:20` (old build) inserts 9 positional values into a table that `src/sign/store.ts:48-58` widens to 16 columns. Deploy the new build to the public server before pointing both at the same DB.
3. `/plan` omits the publication config (see Setup). Publication is exposed only on `GET /api/sign/<id>`.
