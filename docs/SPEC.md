# ResolutionSpec v1

Noa Court stores a ResolutionSpec as the exact UTF-8 JSON string `spec_json`. The resolver in `crates/court-core` fetches declared evidence, extracts typed values, and returns a Verdict v1. Draft with `court_guide`, sample the source, run `spec_lint` and `spec_simulate`, then use `rules_render` to obtain canonical JSON. Replace every example date, threshold, and fixture URL before use.

## Shape and timing

| Field             | Meaning                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`         | Integer `1`.                                                                                                                                   |
| `question`        | Optional human-readable question.                                                                                                              |
| `outcomes`        | 2–10 distinct, nonempty strings in market index order.                                                                                         |
| `observation`     | `{at, baseline_at?, mode, max_delay?}`. `at` must be UTC RFC 3339 ending in `Z` and at or after market close. `baseline_at < at` for `change`. |
| `sources`         | Nonempty ordered array of `{id, tool, params?, request?, expect?, extract?, sanity?, identity?, label?}`; IDs must be unique.                  |
| `aggregate`       | `{method, tolerance?}`; see below.                                                                                                             |
| `decide`          | Typed decision configuration; see below.                                                                                                       |
| `outcome_map`     | Maps every decision result key to an entry in `outcomes`.                                                                                      |
| `on_unavailable`  | `void` or an outcome name. Applied by Court when attempts are exhausted or a verdict is unresolvable.                                          |
| `retry`           | `{max_attempts: 1..10, every: "5m"}`. Durations use `s`, `m`, `h`, or `d`. Court also caps attempts by its own `max_attempts`.                 |
| `rules_text_hash` | Optional hash of displayed rules text, generated by `rules_render`.                                                                            |

`observation.mode` is `historical` for time-addressed evidence or `first_fetch_after` for a snapshot after `at`. Snapshot tools require `max_delay` in the cases listed under lint. A late fetch is `stale`; a candle must have closed. Simulation ignores the observation gate and uses current or latest data, so its result is a preflight, not a future guarantee.

`aggregate.method` is `primary_then_fallback` (first successful source in order), `median` (numeric, at least half of declared sources successful; mean of middle two when even), or `all_agree` (all sources successful, pairwise equal or within `tolerance`). For numeric `all_agree`, `"0.5%"` is relative to the smaller absolute value; `"0.1"` is an absolute difference. Tolerance is required for `all_agree`.

## Source tools

The tool-specific fields below belong in `source.params` unless otherwise stated. Candle tools select the candle containing `observation.at`, and reject one that has not closed.

| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `binance_kline`   | `symbol` required; `interval` defaults to `1m`; `field` is `close` (default) or `open`. Tries `data-api.binance.vision`, then `api.binance.com` for transport, timeout, server, or geo errors.                                                                                                                       | `{"id":"binance","tool":"binance_kline","params":{"symbol":"NEARUSDT","interval":"1m"}}`                                                                                                                                        |
| `okx_candle`      | `instId` required; `bar` defaults to `1m`; `field` is `close` (default) or `open`. Requires a confirmed candle.                                                                                                                                                                                                      | `{"id":"okx","tool":"okx_candle","params":{"instId":"NEAR-USDT","bar":"1m"}}`                                                                                                                                                   |

| `coingecko_price` | `id` and `vs` required; day-level price, not a minute candle. | `github_repo`     | `owner`, `repo`, `field` required; `expect.repo_id` must equal the immutable numeric GitHub repo ID. Snapshot requires `max_delay`.                                                                                                                                                                                  | `{"id":"repo","tool":"github_repo","params":{"owner":"near","repo":"nearcore","field":"stargazers_count"},"expect":{"repo_id":123456789}}` (replace ID after sampling)                                                          |
| `http_json`       | Top-level `request`, `expect`, `identity`, `extract`, optional `sanity`; details below.                                                                                                                                                                                                                              | `{"id":"score","tool":"http_json","request":{"method":"GET","url":"https://example.org/score.json"},"expect":{"status":200,"assert":["$.id == 'noa-test-1'"]},"identity":"asserted","extract":{"path":"$.score","type":"int"}}` |
| `rss_feed`        | `url` in `params` (or top level); parses dated RSS/Atom items into text evidence.                                                                                                                                                                                                                                    | `{"id":"feed","tool":"rss_feed","params":{"url":"https://example.org/feed.xml"}}`                                                                                                                                               |
| `web_text`        | `url` in `params` (or top level); strips script/style/HTML from static page text. Snapshot requires `max_delay`.                                                                                                                                                                                                     | `{"id":"page","tool":"web_text","params":{"url":"https://example.org/news"}}`                                                                                                                                                   |

`http_json.request` accepts `method: GET|POST` (GET default), HTTPS `url`, optional string `headers`, `body`, and `auth: {secret, header?, prefix?}`. The resolver also accepts `params.request`, but top-level `request` is clearer. `secret` names an OutLayer sealed environment variable; never put its value in a spec. URL, headers, and body support `{T:YYYY-MM-DD}`, `{T:YYYYMMDD}`, `{T:unix_ms}`, `{T:unix}`, and `{T:iso}`. `expect.status` defaults to 200. `expect.assert` is an array of assertions such as `$.id == 'noa-test-1'`, `$.active == true`, `$.score >= 50`, or `$.id exists`. The comparison operators are `==`, `!=`, `>=`, `<=`, `>`, `<`; string literals can use single quotes or JSON double quotes. At least one assertion is required unless `identity: "url_only"` explicitly accepts URL-only identity. An `identity` value, when present, must be `asserted` or `url_only`.

`expect.as_of` is an optional RFC 9535 JSONPath to a UTC timestamp or Unix seconds/milliseconds. In resolve mode it must be within `[observation.at, observation.at + max_delay]`; without it the fetch is a snapshot and `max_delay` is required. `extract.path` must select exactly one node (`extract_missing` or `extract_not_unique` otherwise); `extract.type` is `int`, `decimal`, `bool`, `string`, or `timestamp`. `extract.decimals` is an optional integer 0–28 that divides a numeric raw value by `10^decimals`. Positional array indexes or slices require both `extract.allow_index: true` and a nonempty `extract.index_reason`; key-based paths are safer. `sanity.min`, `sanity.max`, and `sanity.max_change_vs_preflight` (for example `"2x"`, with `sanity.preflight_value`) bound numeric values. Failed checks produce source errors, not a guessed outcome. HTTP JSON response size is capped at 2 MiB; text sources at 1 MiB. Public sources use HTTPS.

Source labels are computed from the URL host, regardless of a supplied `label`: `verified` for `api.binance.com`, `data-api.binance.vision`, `www.okx.com`, `okx.com`, `api.exchange.coinbase.com`, `api.coinbase.com`, `api.coingecko.com`, `api.github.com`, `rpc.mainnet.near.org`, `rpc.testnet.near.org`, `archival-rpc.mainnet.near.org`, `archival-rpc.testnet.near.org`, `free.rpc.fastnear.com`, `rpc.mainnet.fastnear.com`, `test.rpc.fastnear.com`, `near-testnet.lava.build`, or `near.lava.build`; every other host is `self_declared`. The code's allowlist still contains `near-testnet.lava.build`, but that endpoint is discontinued; do not configure it as an RPC. A verified label identifies an allowlisted host, not the truth of its contents or current availability.

## Decisions and unavailable evidence

| `decide.kind` | Fields                                                                                                                            | `outcome_map` result keys                                                          |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `threshold`   | `op: >=                                                                                                                           | >                                                                                  | <=          | <`, decimal `value` | `true`, `false` |
| `buckets`     | Ascending decimal `edges`, `inclusive: "lower"`. Edge equality enters the higher bucket; `n` edges create `n+1` buckets.          | `"0"` through `"n"`                                                                |
| `equals`      | `value` string, decimal, or boolean                                                                                               | `true`, `false`                                                                    |
| `bool`        | No extra fields; extracted value must be boolean.                                                                                 | `true`, `false`                                                                    |
| `change`      | `tie` names the tie outcome; compares numeric value at `at` with `baseline_at`.                                                   | `up`, `down`, `tie`                                                                |
| `text_judge`  | `question`, nonempty `yes_criteria`, optional `no_criteria`, `window: {from,to}` with `from < to`, `default_if_no_evidence: "yes" | "no"`. Sources must be `rss_feed`, `web_text`, or `http_json` with string extract. | `yes`, `no` |

For `text_judge`, RSS items need a publication date in the inclusive window. Up to 20 items and 12,000 characters are sent as **data** to three NEAR AI jurors. Each vote must cite an item in the window and verbatim, nonempty quotes for a yes/no answer. All three votes must be valid, agree on yes or no, and have confidence at least 0.7. Otherwise resolution retries. No evidence in the window uses `default_if_no_evidence` without calling jurors. Evidence text is untrusted; injection-like phrases are flagged in the reason when the panel is inconclusive.

`resolved` has an `outcome` and zero-based `outcome_index`. `retry_after` has a UTC retry time when an attempt remains. `unresolvable` has no decided outcome. Court then applies `on_unavailable`: `void` leaves an unresolvable item for the market void path, while an outcome name makes Court resolve to that outcome and sets `applied_on_unavailable: true` on the receipt. The raw resolver verdict remains in the receipt.

## Canonicalization, lint, and Verdict

Use RFC 8785 JSON Canonicalization Scheme (JCS), then `spec_hash = "sha256:" + lowercase_hex(SHA256(UTF8(spec_json)))`. Court hashes the **exact string supplied** and does not canonicalize it. `rules_render` returns canonical `spec_json` and its hash. Hash source evidence separately; `source.evidence_sha256` is hex SHA-256 of the fetched response bytes without a `sha256:` prefix.

Lint returns `{ok, errors: [{code,path,message}], labels}`. The code sets `message` to the code with underscores replaced by spaces. Its emitted codes are:

| Code                                                                                            | Check                                                                                              |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `spec_invalid`, `version_unsupported`                                                           | Parseable JSON and version 1.                                                                      |
| `outcomes_count`                                                                                | 2–10 unique nonempty outcome names.                                                                |
| `observation_invalid`, `observation_before_close`                                               | UTC `at`, valid mode/delay, and market close no later than `at` when context is provided.          |
| `duplicate_source_id`, `unknown_tool`, `source_params_invalid`                                  | Source IDs, known tools, and required parameters.                                                  |
| `identity_assert_required`, `jsonpath_invalid`, `positional_index_forbidden`, `decimal_invalid` | GitHub/HTTP JSON identity, valid JSONPaths, indexed path exception, and decimals/sanity/tolerance. |
| `max_delay_required`, `price_needs_two_sources`                                                 | Snapshot freshness and at least two price tools for a price decision.                              |
| `decide_invalid`, `buckets_invalid`, `change_needs_baseline`, `text_judge_invalid`              | Decision grammar and time boundaries.                                                              |
| `outcome_map_incomplete`, `outcome_map_unknown_outcome`                                         | Every result key maps to a declared outcome.                                                       |
| `aggregate_invalid`, `on_unavailable_invalid`, `retry_invalid`                                  | Aggregate method/tolerance, unavailable action, and retry policy.                                  |

Price-source lint specifically counts price tools and requires two when `decide.kind` is `threshold`, `buckets`, or `change` and exactly one price tool is supplied. It does not prove that both sources quote the same asset. Snapshot `max_delay` lint applies to GitHub, CoinGecko, web text, HTTP JSON without `expect.as_of`, and `near_view` in `first_fetch_after` mode. The resolver also performs runtime freshness checks; run lint before funding a market.

Verdict v1 has this JSON shape (nullable fields are always present except `lint`, which appears in lint mode):

```json
{
  "v": 1,
  "resolver_version": "0.1.0",
  "spec_hash": "sha256:<64 lowercase hex characters>",
  "mode": "resolve",
  "status": "resolved",
  "outcome": "Yes",
  "outcome_index": 0,
  "value": "3.41",
  "retry_after": null,
  "reason": "threshold 3.41 true",
  "sources": [
    {
      "id": "binance",
      "ok": true,
      "value": "3.41",
      "as_of": "2026-11-13T10:00:00Z",
      "url": "https://data-api.binance.vision/...",
      "evidence_sha256": "<64 hex characters>",
      "error": null
    }
  ],
  "jurors": null
}
```

`mode` is `resolve`, `simulate`, or `lint`; `value` is the aggregated typed value rendered as a string, or null for text evidence. Each source reports success, value, observation time, URL, response hash, and error code. `jurors` is null or an array of `{model, answer, confidence, quotes, item_ref, valid, invalid_reason}`. `lint` mode adds the lint report. See the saved [resolver outputs](../resolver/examples/README.md).

## Worked specs

These are complete examples of the five requested patterns. Dates and source URLs are illustrative; update them and run lint/simulate before use.

### Price threshold (Binance with OKX fallback)

```json
{
  "version": 1,
  "question": "Will NEAR/USDT 1m close be at least 3.40?",
  "outcomes": ["Yes", "No"],
  "observation": {
    "at": "2026-12-01T12:00:00Z",
    "mode": "historical",
    "max_delay": "30m"
  },
  "sources": [
    {
      "id": "binance",
      "tool": "binance_kline",
      "params": { "symbol": "NEARUSDT", "interval": "1m" }
    },
    {
      "id": "okx",
      "tool": "okx_candle",
      "params": { "instId": "NEAR-USDT", "bar": "1m" }
    }
  ],
  "aggregate": { "method": "primary_then_fallback" },
  "decide": { "kind": "threshold", "op": ">=", "value": "3.40" },
  "outcome_map": { "true": "Yes", "false": "No" },
  "on_unavailable": "void",
  "retry": { "max_attempts": 3, "every": "5m" }
}
```

If Binance's closed candle is `3.41`, the result key is `true`, yielding `Yes` at index 0. The [saved A1 example](../resolver/examples/a1_near_threshold.spec.json) includes a real simulation output.

### Three price buckets

```json
{
  "version": 1,
  "question": "Which BTC/USDT close bucket?",
  "outcomes": ["Below", "Middle", "Above"],
  "observation": {
    "at": "2026-12-01T12:00:00Z",
    "mode": "historical",
    "max_delay": "30m"
  },
  "sources": [
    {
      "id": "binance",
      "tool": "binance_kline",
      "params": { "symbol": "BTCUSDT", "interval": "1m" }
    },
    {
      "id": "okx",
      "tool": "okx_candle",
      "params": { "instId": "BTC-USDT", "bar": "1m" }
    }
  ],
  "aggregate": { "method": "primary_then_fallback" },
  "decide": {
    "kind": "buckets",
    "edges": ["99900", "100100"],
    "inclusive": "lower"
  },
  "outcome_map": { "0": "Below", "1": "Middle", "2": "Above" },
  "on_unavailable": "void",
  "retry": { "max_attempts": 3, "every": "5m" }
}
```

`99900` enters `Middle`; `100100` enters `Above`.

### NEAR view with base units

```json
{
  "version": 1,
  "question": "Does user3 hold at least 10500 NPOINT?",
  "outcomes": ["Yes", "No"],
  "observation": {
    "at": "2026-12-01T12:00:00Z",
    "mode": "first_fetch_after",
    "max_delay": "10m"
  },
  "sources": [
    {
      "id": "balance",
      "tool": "near_view",
      "params": {
        "network": "testnet",
        "contract": "point.noamarket.testnet",
        "method": "ft_balance_of",
        "args": { "account_id": "user3.noamarket.testnet" },
        "rpcs": [
          "https://test.rpc.fastnear.com",
          "https://rpc.testnet.near.org"
        ]
      },
      "extract": { "type": "decimal", "decimals": 18 }
    }
  ],
  "aggregate": { "method": "primary_then_fallback" },
  "decide": { "kind": "threshold", "op": ">=", "value": "10500" },
  "outcome_map": { "true": "Yes", "false": "No" },
  "on_unavailable": "void",
  "retry": { "max_attempts": 3, "every": "5m" }
}
```

If both RPCs return the same `10500000000000000000000` base-unit balance, extraction yields `10500` and `Yes`.

### HTTP JSON with identity assertion

```json
{
  "version": 1,
  "question": "Is the published score at least 50?",
  "outcomes": ["Yes", "No"],
  "observation": {
    "at": "2026-12-01T12:00:00Z",
    "mode": "first_fetch_after",
    "max_delay": "10m"
  },
  "sources": [
    {
      "id": "score",
      "tool": "http_json",
      "request": { "method": "GET", "url": "https://example.org/score.json" },
      "expect": { "status": 200, "assert": ["$.id == 'noa-test-1'"] },
      "identity": "asserted",
      "extract": { "path": "$.score", "type": "int" },
      "sanity": { "min": "0", "max": "100" }
    }
  ],
  "aggregate": { "method": "primary_then_fallback" },
  "decide": { "kind": "threshold", "op": ">=", "value": "50" },
  "outcome_map": { "true": "Yes", "false": "No" },
  "on_unavailable": "void",
  "retry": { "max_attempts": 3, "every": "5m" }
}
```

For `{"id":"noa-test-1","score":51}`, the result is `Yes`. If the ID changes, the source returns `assert_failed`; Court retries and then follows `on_unavailable`.

### RSS text judge

```json
{
  "version": 1,
  "question": "Did Kent ship Noa Court v2 during the window?",
  "outcomes": ["Yes", "No"],
  "observation": {
    "at": "2026-12-01T12:00:00Z",
    "mode": "first_fetch_after",
    "max_delay": "10m"
  },
  "sources": [
    {
      "id": "feed",
      "tool": "rss_feed",
      "params": { "url": "https://example.org/feed.xml" }
    }
  ],
  "aggregate": { "method": "primary_then_fallback" },
  "decide": {
    "kind": "text_judge",
    "question": "Did Kent ship Noa Court v2?",
    "yes_criteria": [
      "A dated item explicitly announces shipment of Noa Court v2"
    ],
    "no_criteria": ["Plans and rumors do not count"],
    "default_if_no_evidence": "no",
    "window": { "from": "2026-12-01T11:00:00Z", "to": "2026-12-01T12:00:00Z" }
  },
  "outcome_map": { "yes": "Yes", "no": "No" },
  "on_unavailable": "void",
  "retry": { "max_attempts": 3, "every": "5m" }
}
```

An in-window dated item needs three valid, agreeing juror votes for `Yes`; an empty in-window feed resolves `No` through `default_if_no_evidence`.
